# Credit Default Prediction — MLOps Project

## Описание проекта

Проект разработан в рамках курса «Автоматизация процессов разработки и тестирования моделей машинного обучения».

**Цель проекта** — разработать воспроизводимый процесс подготовки данных, обучения, тестирования и развёртывания модели машинного обучения для прогнозирования вероятности дефолта клиента (Probability of Default, PD).

Проект охватывает основные этапы жизненного цикла ML-модели: от подготовки данных до предоставления прогнозов через REST API и мониторинга распределительного сдвига входных признаков.

## 1. Датасет

Используется набор данных **Default of Credit Card Clients** из UCI Machine Learning Repository.

- Количество наблюдений: 30 000.
- Количество столбцов после подготовки: 30.
- Целевая переменная: `default`.
- Задача: бинарная классификация.
- Пропущенные значения после подготовки: отсутствуют.

Целевая переменная принимает значения:

- `0` — отсутствие дефолта.
- `1` — дефолт клиента.

## 3. Подготовка данных

Модуль `src/prepare.py` выполняет очистку и преобразование исходного датасета.

Основные операции:

- Удаление идентификатора клиента.
- Нормализация категориальных признаков.
- Подготовка целевой переменной.
- Создание дополнительных признаков.
- Сохранение обработанных данных.

### Feature Engineering

Создаются следующие признаки:

| Признак | Описание |
|---|---|
| `AVG_BILL_AMT` | Средний размер выставленных счетов |
| `AVG_PAY_AMT` | Средний размер платежей |
| `DELAY_MONTHS` | Количество месяцев с задержками платежей |
| `MAX_DELAY` | Максимальная задержка платежа |
| `CREDIT_UTILIZATION` | Показатель использования кредитного лимита |
| `AGE_GROUP` | Возрастная группа клиента |

Подготовленные данные сохраняются в:

`data/processed/credit_default_processed.csv`

## 4. Обучение модели

Для прогнозирования дефолта используется логистическая регрессия.

Процесс обучения реализован с использованием `Pipeline` из Scikit-learn и включает:

- Обработку пропущенных значений.
- Масштабирование числовых признаков.
- Кодирование категориальных признаков.
- Подбор гиперпараметров с помощью GridSearchCV.
- Оценку качества модели.

### Результаты экспериментов

| Метрика | Значение |
|---|---:|
| ROC-AUC | 0,7468 |
| Recall | 0,6006 |

Выбранные параметры модели:

- `C = 10`
- `class_weight = balanced`

Обученная модель сохраняется в:

`models/credit_default_model.joblib`

## 7. REST API

Для предоставления прогнозов разработано приложение на FastAPI.

Основные эндпоинты:

| Метод | Адрес | Назначение |
|---|---|---|
| GET | `/` | Проверка доступности API |
| POST | `/predict` | Прогнозирование вероятности дефолта |

Локальный запуск:

```bash
python -m uvicorn src.api:app --host 127.0.0.1 --port 8000
```

Интерактивная документация Swagger:

http://127.0.0.1:8000/docs

### Формат ответа

```json
{
  "prediction": 1,
  "default_probability": 0.8310913391396004
}
```

Значение `prediction` обозначает прогнозируемый класс, а `default_probability` — оценённую моделью вероятность дефолта.

## 9. Мониторинг Data Drift

Для обнаружения изменения распределений входных признаков реализован метод **Population Stability Index (PSI)**.

Формула:

\[
PSI = \sum_{i=1}^{k}(p_i-q_i)\ln\frac{p_i}{q_i}
\]

где:

- \(p_i\) — доля наблюдений в текущей выборке;
- \(q_i\) — доля наблюдений в эталонной выборке.

Для интерпретации применяются ориентировочные пороги:

| PSI | Интерпретация |
|---|---|
| Менее 0,1 | Незначительный сдвиг |
| От 0,1 до 0,25 | Умеренный сдвиг |
| Более 0,25 | Существенный сдвиг |

Пороги являются эвристическими и не заменяют статистическую проверку.

### Запуск мониторинга

```bash
python -m src.run_monitoring
```

Результаты сохраняются в:

`reports/data_drift_report.csv`

### Базовый эксперимент

Исходный датасет разделён на две непересекающиеся выборки.

Для семи признаков получены значения PSI от 0,0002 до 0,0020, что соответствует незначительным изменениям распределений.

### Эксперимент с искусственным сдвигом

Для проверки чувствительности мониторинга кредитные лимиты `LIMIT_BAL` в контрольной выборке были искусственно увеличены на 50%.

Полученные результаты:

| Сценарий | PSI для LIMIT_BAL |
|---|---:|
| Исходные данные | 0,0008 |
| Искусственный сдвиг | 0,7633 |

Мониторинг обнаружил существенный сдвиг распределения изменённого признака.

Эксперимент является демонстрацией механизма обнаружения Data Drift, а не свидетельством реального изменения распределения клиентских данных.
