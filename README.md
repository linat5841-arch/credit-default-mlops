# Credit Default Prediction — MLOps Project

## Описание проекта

Проект разработан в рамках курса «Автоматизация процессов разработки и тестирования моделей машинного обучения».

**Цель проекта** — построить воспроизводимый процесс подготовки данных, обучения, тестирования, развёртывания и мониторинга модели машинного обучения для прогнозирования вероятности дефолта клиента (Probability of Default, PD).

Реализованы подготовка данных, Feature Engineering, валидация качества данных, обучение модели, управление экспериментами, версионирование данных, автоматическое тестирование, CI, REST API, Docker и мониторинг распределительного сдвига.

## 1. Датасет

Используется **Default of Credit Card Clients** из UCI Machine Learning Repository.

- Количество наблюдений: 30 000.
- Количество столбцов после подготовки: 30, включая целевую переменную.
- Целевая переменная: `default`.
- Задача: бинарная классификация.
- Пропущенные значения после подготовки: отсутствуют.

Значения целевой переменной:

- `0` — отсутствие дефолта.
- `1` — дефолт клиента.

## 3. Подготовка данных и Feature Engineering

Модуль `src/prepare.py` выполняет очистку и преобразование исходного датасета.

Основные операции:

- Удаление идентификатора клиента.
- Нормализация категориальных признаков.
- Подготовка целевой переменной.
- Создание дополнительных признаков.
- Сохранение обработанных данных.

### Создаваемые признаки

| Признак | Описание |
|---|---|
| `AVG_BILL_AMT` | Средний размер выставленных счетов |
| `AVG_PAY_AMT` | Средний размер платежей |
| `DELAY_MONTHS` | Количество месяцев с задержками платежей |
| `MAX_DELAY` | Максимальная задержка платежа |
| `CREDIT_UTILIZATION` | Показатель использования кредитного лимита |
| `AGE_GROUP` | Возрастная группа клиента |

Результат подготовки:

`data/processed/credit_default_processed.csv`

### Валидация данных

Модуль `src/validate_data.py` реализует проверки качества данных с использованием Great Expectations.

Проверяются структура датасета, допустимые значения признаков и ограничения качества данных.

Реализовано 70 expectation-правил.

## 4. Обучение и оценка модели

Для прогнозирования дефолта используется логистическая регрессия.

Процесс обучения реализован в `src/train.py` с использованием Scikit-learn Pipeline.

Pipeline включает:

- Обработку пропущенных значений.
- Масштабирование числовых признаков.
- Кодирование категориальных признаков.
- Логистическую регрессию.

Для подбора гиперпараметров применяется GridSearchCV с пятиблочной стратифицированной кросс-валидацией.

**Метрика выбора модели — ROC-AUC.**

Разделение данных:

- Обучающая выборка: 24 000 наблюдений.
- Тестовая выборка: 6 000 наблюдений.
- Доля дефолтов: приблизительно 22,12%.

Подбор параметров выполняется на обучающей выборке. Тестовая выборка используется для итоговой оценки выбранной модели.

### Лучшие гиперпараметры

- `C = 10.0`
- `class_weight = balanced`

### Результаты обучения

| Метрика | Значение |
|---|---:|
| ROC-AUC на кросс-валидации | 0.7601 |
| Accuracy на тесте | 0.7437 |
| Precision на тесте | 0.4416 |
| Recall на тесте | 0.6006 |
| F1 на тесте | 0.5089 |
| ROC-AUC на тесте | 0.7468 |

ROC-кривая сохраняется в:

`reports/figures/roc_curve.png`

Обученная модель сохраняется в:

`models/credit_default_model.joblib`

## 5. MLflow — управление экспериментами

Для регистрации и сравнения экспериментов используется MLflow.

Модуль `src/run_experiments.py` реализует сравнение пяти конфигураций модели с использованием стратифицированной кросс-валидации.

### Экспериментальные конфигурации

| C | class_weight | ROC-AUC CV |
|---|---|---:|
| 0.01 | None | 0.7570 |
| 0.1 | None | 0.7586 |
| 1.0 | None | 0.7589 |
| 1.0 | balanced | 0.7601 |
| 10.0 | balanced | 0.7601 |

Значения ROC-AUC округлены до четырёх знаков.

Лучшая конфигурация определяется по неокруглённым результатам кросс-валидации.

После выбора модели выполняется отдельная итоговая оценка на тестовой выборке.

MLflow сохраняет параметры, метрики и модельные артефакты.

Запуск экспериментов:

```bash
python -m src.run_experiments
```

## 6. DVC — воспроизводимость данных и обучения

DVC используется для контроля версий данных, модели и этапов ML-pipeline.

Конфигурация pipeline находится в `dvc.yaml`, а состояние зависимостей и результатов фиксируется в `dvc.lock`.

### Этапы pipeline

**prepare → train**

Этап `prepare`:

- Вход: исходный датасет.
- Скрипт: `src/prepare.py`.
- Выход: подготовленный датасет.

Этап `train`:

- Вход: подготовленный датасет.
- Скрипт: `src/train.py`.
- Выход: обученная модель.

Воспроизведение pipeline:

```bash
dvc repro
```

Проверка актуальности:

```bash
dvc status
```

При последней проверке получен результат:

```text
Data and pipelines are up to date.
```

## 10. Мониторинг Data Drift

Для обнаружения изменения распределений входных признаков реализован Population Stability Index (PSI).

Основная функция находится в:

`src/monitor.py`

Сценарий мониторинга:

`src/run_monitoring.py`

### Формула PSI

\[
PSI = \sum_{i=1}^{k}(p_i-q_i)\ln\frac{p_i}{q_i}
\]

где:

- \(p_i\) — доля наблюдений в текущей выборке.
- \(q_i\) — доля наблюдений в эталонной выборке.

### Интерпретация

| PSI | Интерпретация |
|---|---|
| Менее 0.10 | Незначительный сдвиг |
| От 0.10 до 0.25 | Умеренный сдвиг |
| От 0.25 | Существенный сдвиг |

Пороговые значения являются эвристическими.

### Запуск мониторинга

```bash
python -m src.run_monitoring
```

Отчёт сохраняется в:

`reports/data_drift_report.csv`

### Эксперимент 1. Baseline

Исходный датасет разделён на две непересекающиеся выборки.

Для семи признаков значения PSI находятся в диапазоне от 0.0002 до 0.0020.

Существенного сдвига не обнаружено.

### Эксперимент 2. Искусственный Data Drift

Для проверки чувствительности PSI значения `LIMIT_BAL` в контрольной выборке увеличены на 50%.

| Сценарий | PSI |
|---|---:|
| Baseline | 0.0008 |
| Synthetic drift | 0.7633 |

После изменения распределения PSI превысил порог существенного сдвига.

Автоматические тесты в `tests/test_monitor.py` проверяют одинаковые распределения, обнаружение сдвига и обработку некорректных входных данных.

Эксперимент с искусственным сдвигом демонстрирует работу механизма мониторинга, но не свидетельствует о реальном изменении клиентских данных.

## 12. Воспроизведение проекта

Для проверки проекта на другом компьютере:

1. Клонировать GitHub-репозиторий.
2. Создать Python-окружение и установить зависимости из `requirements.txt`.
3. Настроить доступ к DVC remote и выполнить `dvc pull`.
4. Проверить воспроизводимость через `dvc status` и при необходимости `dvc repro`.
5. Запустить тесты и проверки качества кода.
6. Изучить результаты MLflow или повторно запустить эксперименты.
7. Собрать Docker-образ и запустить FastAPI.
8. Выполнить запрос к `/predict`.
9. Запустить PSI-мониторинг и изучить CSV-отчёт.

Доступ к Google Drive remote предоставляется отдельно. Без соответствующих прав `dvc pull` может быть недоступен.
